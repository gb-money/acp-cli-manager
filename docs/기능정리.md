# 프로젝트 구현에 필요한 필수 기능을 정리한다.

## 대화 진행 흐름

1. 사용자가 프롬프트를 입력 후 전송한다. (session/prompt)
2. 에이전트는 프롬프트에 맞는 응답을 생성하며, 생성되는 경우의 수는 아래와 같다.
  - session/update 내 params.update.sessionUpdate : agent_thought_chunk 또는 agent_message_chunk
  - method: session/request_permission
  - method: fs/read_text_file 또는 fs/write_text_file

3. 응답에 알맞은 UI를 구현한다. 구현 방법은 아래와 같다.
  - session/update 가 넘어오는 경우 : params.update.sessionUpdate에 맞는 UI 구성
    - agent_thought_chunk : 생각과정 UI 표시
    - agent_message_chunk : 메시지 버블 표시
    - tool_call : tool에 맞는 UI 표시 (현재 구현된 UI 없으므로 TODO로 정리)
    - tool_call_update : tool_call UI 상태를 업데이트 (현재 구현된 UI 없으므로 TODO로 정리)
  - session/request_permission 이 넘어오는 경우
    - params.options 에 담겨있는 옵션 정보를 표시함 (ShowRequestPermission)
      - 사용자가 옵션을 선택한 경우 : result.outcome 구조로 rpc 응답
      - 취소하려는 경우 : result.outcome.outcome : cancelled 로 rpc 응답
